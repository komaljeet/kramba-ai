A 1B-parameter model normally wants roughly 10 GB before it has processed a single token — about 4 GB of weights, 4 GB of gradients, and optimiser state on top. On a 6 GB card the standard advice is to rent an A100.

How it is done

Five published techniques, one working integration

No new algorithms. Every piece is published and attributed. The work is making them run together and measuring what that costs.

What 2.33× means: Weight tensors only (not total VRAM). fp32 (32 bits) → ternary stored as int8 (8 bits) + per-matrix fp32 scale. Theoretical 20× (log₂3 ≈ 1.58 bits), practical 2.33× after scale overhead.

35% sparsity: ~1/3 of weights round to exactly 0 — zeros are spread across rows, not whole-row collapse.

QAT only: Must train from scratch with straight-through estimator (STE). Post-hoc quantization loses the learned dynamics. --ternary is ON by default in production runs.

No training VRAM win: fp32 shadow weights stay resident for gradient updates. Ternary saves checkpoint size and inference memory only.

Ternary collapse at init: Fresh layers can zero out before learning (Issue #109). Fixed by warm-starting trunk from pre-trained checkpoint.

Group-wise scales tested (Issue #146): Finer per-group scales lose to per-tensor — storage ratio improves with width but quality doesn't.

Two of these did not previously work together. Tied embeddings share one tensor between the input lookup and the output layer, and the offload system rejected that outright: it assigns every parameter to exactly one block, and this tensor belongs to two. The combination was guarded off as unsupported.

The fix is to pin it — a parameter reachable from two modules is never evicted, because the forward pass uses it at both ends and no single block's residency window covers both uses. The cost is one vocabulary table held resident, 250 MB at 1B scale. Lifting that guard also re-enabled 13 of the subsystem's own tests, which had been silently skipped ever since tying became the default, because every one of them builds a tied model and hit the guard at construction.

Update 2026-09-26: the previously OOM combination (tied embeddings + CPU offload) now fits without OOM when combined with chunked cross-entropy (--chunked-loss 512). A 5-step fp32 test at 1.11B parameters ran at 79% of 6 GB = 4.85 GB without OOM. The pinned tied table (~206 MB bf16) plus chunked loss (~1.5 GB saved) makes the previously-untested four-technique stack (BCD + offload + tied + chunked) fit together in memory. This was a 5-step memory-fit test, not a graded training run.

Update 2026-10-11: a separate, unrelated bug in the offload path itself (not the tying) could swap weights during training whenever --offload ran with prefetch on — see the correction at the top of this page. The "fits" numbers above hold; any "trains correctly" claim built on an offloaded run needs re-verifying.

The trade-off: Tied embeddings vs offload

Tied saves params, but pins 250 MB on GPU with offload

Tied embeddings saves ~103M params (one vocab table instead of two). But with CPU offload, the shared table must stay pinned on GPU (used by both token_embedding and decoder), costing 250 MB that can never be offloaded. At 1.07B params (2048 d_model, 24L, 64 heads, tied) the pinned 250 MB + offload overhead pushes past 6 GB → OOM.

Without tied embeddings (1.11B params): all blocks offloadable, VRAM flat at 3.48/4.51 GB, ran without OOM. The blog post's 1.07B at 4.00 GB claim was measured without BCD offload. (2026-10-11: "trains smoothly" overstated what was verified — see the correction above; it fit and ran without crashing, which is what was actually confirmed at the time.)

Where the memory actually goes

Measured on live 1.11B run at step 1350 (untied) + 5-step fp32 test (tied + offload + chunked)

ItemSize
Computing the loss — 4,096 positions × 50,257 vocabulary~1,500 MB
Chunked loss (512 positions) saves~1,500 MB
CUDA context, kernels, workspaces~400 MB
Weights (ternary)~960 MB
Optimiser state (BCD: one block at a time)~200 MB
Layer activations (grad checkpoint)~50 MB
Pinned tied table (if tied)~250 MB

The largest consumer is not the model. It is the cross-entropy over the vocabulary — roughly three times the size of the weights. Chunked loss (512 positions at a time) recomputes logits in backward instead of keeping them, saving ~1.5 GB. This is what made the previously OOM combination (tied + offload) work: the pinned tied table costs ~250 MB, but chunked loss returns ~1,500 MB, leaving headroom.

What it costs

The part usually left out

Fitting is not training. Compute is the wall, and no memory technique touches it.

The year is not bad code. It is 36 billion tokens. The 1.11B run at 1,579 tok/s needs ~300 days for Chinchilla (36B tokens). Every optimisation left, added up optimistically, is 20–25%. The cost is 6 × params × tokens / card_speed, and only the first two terms are still open.

Limits

  • The architecture is a reimplementation of published work — gated DeltaNet, GLA/Mamba-2 gating, Mamba/RWKV-7 convolution and output gate. The code is original; the design is not.
  • Constant-memory inference is a property of that entire model family, not of this work.
  • Nothing above 48M has been trained to convergence here. Every scaling statement is measured below that size and should not be extrapolated past it.
  • Comparisons are single-seed: training the same model three times, changing only the starting random numbers, moved the result by 0.089. Some differences reported are smaller than that and cannot be separated from luck without repeating across seeds.

One rule, applied before any measurement: if the thing being tested were broken, would this test catch it? Answer before seeing the result. A test that cannot fail turns a bug into a published number.

Dead ends, recorded on purpose

  • torch.compile is 2.4x SLOWER on this architecture (4 independent measurements).
  • Mixture-of-experts loses to simply scaling the dense model.
  • Tensor-train factorisation loses (half params, 22% worse).
  • GHOST (weight extrapolation) loses to doing nothing.
  • Looped/weight-shared models lose (3 layers × 4 loses to 12 layers by 11x noise floor).
